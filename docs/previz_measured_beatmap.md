## 1. 量測方法

主角在 previz 是唯一的高飽和紅色物體，用紅色遮罩逐幀切出主體，記錄三條曲線：

| 欄位 | 意義 | 對應的 rig 資訊 |
|---|---|---|
| `area` | 主體佔畫面面積比 | 鏡頭推拉 / 主體遠近 |
| `cx` | 主體重心水平位置（0=左緣, 1=右緣） | 畫幅內橫向走位 |
| `cy` | 主體重心垂直位置（0=上緣, 1=下緣） | 縱向構圖高低 |

模型沒有 rig，所以不比骨骼——比 **rig animation 投影到 2D 畫幅上的運動軌跡**，
這是唯一可驗證的量。

剪接點判定：`area` 相對跳變 >70%，或主體可見性翻轉。

## 2. 實測剪接點

```
 t=1.17s   scale-jump   area 0.0740 → 0.1511
 t=1.50s   scale-jump   area 0.3022 → 0.0117      ← 最明顯的一刀
 t=2.00s   scale-jump   area 0.0143 → 0.1468
 t=2.70s   scale-jump   area 0.3098 → 0.0023      ← 第二明顯
 t=4.57s   visibility   area 0.2105 → 0.0000
```
另有兩個構圖切換（`cy` 突變，`area` 未跨門檻）：**t≈0.17s**、**t≈0.67s**。

**5 秒內共 8 個鏡頭，平均每鏡 0.6 秒。這是一段快剪 previz。**

### 對先前目測版的三處重要修正

1. **0.85s 不是剪接點。** 真正的刀在 **1.17s**。
2. **「等距追蹤長鏡」不在 2.85–5.00，而是 C（1.50–2.00，僅 0.5 秒）。**
   `area` 在這 0.5 秒維持 0.0115 幾乎不動，是全片唯一真正的等距鏡。
3. **E（2.70–4.57）不是單調拉遠，是非單調起伏**，`area` 在 3.40s 衝到峰值 0.14 後回落。
   單次生成必崩，**必須拆成 E1 / E2**：
   - **E1** 2.70–3.40（0.70s）：主體由左緣入畫，`cx` 0.01→0.50，`area` 0.002→0.14
   - **E2** 3.40–4.57（1.17s）：置中擺動後拉遠，`area` 0.14→0.043

## 4. Beat ↔ Prompt 對照（`prompts/omni11_beat_prompts.md`）

既有的 prompt 本體不用改，改的是**掛在哪個 beat、生成多長、用哪張 reference**。

| 實測 Beat | 用哪段 prompt | 生成長度 | Reference 圖 |
|---|---|---|---|
| A1 + A2 | **合併，用 Beat C prompt（背向遠離）** | 2s，取 0.67s | 達摩背面 |
| A3 | Beat A prompt（接近） | 2s，取 0.50s | 達摩正面・滑板車 |
| B | Beat B prompt（逼近特寫） | 2s，取 0.33s | 達摩正面近景 |
| C | **Beat E1 prompt（等距追蹤）** | 2s，取 0.50s | 達摩正面・滑板車 |
| D | Beat B prompt，Camera 段改為緩速推進 | 2s，取 0.70s | 達摩正面近景 |
| E1 | **Beat D prompt（越肩／由左入畫）** | 2s，取 0.70s | 達摩 3/4 背側 |
| E2 | Beat E2 prompt（拉遠收尾） | 2s，取 1.17s | E1 末幀 |
| F | Beat C prompt，Camera 改為靜止 | 2s，取 0.30s | 達摩背面 |

**沒有任何一個 beat 超過 1.2 秒**——這對 Omni 1.1 的 identity 保持是好消息，
每一鏡都遠在 3 秒門檻之內，漂移風險低。

## 5. 驗收流程

```bash
# 抽該 beat 的基準曲線（例：C，1.50s 起 0.50s）
python3 tools/motion_match.py extract previz_part2.mp4 \
        --in 1.50 --duration 0.50 --out ref_C.csv

# 抽成品曲線
python3 tools/motion_match.py extract beatC_take2.mp4 --out gen_C.csv

# 比對
python3 tools/motion_match.py compare ref_C.csv gen_C.csv --beat E1
```

輸出四項判定：**主體尺度曲線 / 水平走位 / 垂直走位 / 運動方向**，
逐項 PASS / FAIL，FAIL 時直接印出對應的重 roll 建議。

`--beat` 決定容差。等距鏡（C）容差最緊（scale 0.10），
越肩鏡（E1）最鬆（scale 0.30）——因為那一鏡本來就難。

### 容差表

| Beat 類型 | scale 容差 | 位置容差 | 理由 |
|---|---|---|---|
| A / C / E2（推、拉） | 0.18 | 0.08 | 單調變化，好對 |
| B / D（快速推近） | 0.22 | 0.10 | 變化陡，允許節奏微差 |
| **C（等距）** | **0.10** | **0.06** | area 必須近乎平坦，漂了就是失敗 |
| **E1（越肩／入畫）** | **0.30** | **0.14** | 前景剛體 + 大位移，本來就難 |

## 6. 這個測試抓得到什麼、抓不到什麼

**抓得到：**
- 主體遠近曲線對不對（鏡頭推拉節奏）
- 主體在畫幅裡的走位對不對
- 運動方向有沒有搞反（推變拉）
- 主體有沒有中途消失或閃爍

**抓不到（仍需人眼過 QC checklist）：**
- 形狀崩壞（長脖子、變人形）——面積比可能仍然正確
- 材質／色溫漂移
- 招牌文字亂寫
- 印刷臉部形變

**所以是「量測 + 人眼」兩層，不是二選一。**
量測負責運動軌跡，人眼負責 §7 QC checklist 的保真與風格項。
